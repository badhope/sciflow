# SciFlow 第三方审计报告（2026-10-29 · v1.9.0）

审计范围：全仓 54,228 行 TS/TSX（388 文件）、25 个服务端模块、11 个前端页面。
方法：逐文件通读 + 运行时实测 + 6 个同领域开源项目源码级对标。

## 一、真实定位（去掉宣传语）

**不是「AI 写论文工具」，而是「科研产出的可审计流水线」。**

通用 deep-research 工具（GPT-Researcher / STORM / open_deep_research）产出的是「一份带引用的报告」，
结束即交付。SciFlow 的差异化在**产出之后的工程化约束**：

| 差异点 | 通用方案 | SciFlow 的真实实现（代码可证） |
|---|---|---|
| 质量判定可复现 | LLM 打分（同一稿漂移 27-59 分） | `packages/core/src/quality-audit.ts` 确定性规则引擎，同文本同分同指纹（FNV-1a），质量门以此为准 |
| 引用可追溯 | 生成式引用（易编造） | `[n]` 锚点 → citations 表 → references 表三级可追；`citation-audit` 七类硬判定（v1.9 前只有三类） |
| 名实相符检测 | 无 | `NO_EXPERIMENT_DISCLAIMER` × `EXPERIMENT_RESULT_CLAIM` 交叉检测「没做实验却声称实验结论」 |
| 过程可回炉 | 一次生成 | LangGraph `interrupt` 人工确认 + Reflexion 定向回炉（按最低分两维给修订指令，最多 3 轮，取最高分轮） |
| 数据主权 | 云 SaaS | 单机 SQLite + Key 本地加密（AES-256-GCM，`.sciflow.key` 0600） |

**结论**：优势不在「能不能写」，而在「写完敢不敢投」。这一点在代码里是真的（有测试锁），不是话术。

## 三、对标（源码级，非 README 级）

|---|---|---|---|---|---|
| **PaperQA2**（9.5k★, Apache-2.0） | 工具选择 agent（`agents/main.py` ToolSelector） | 论文搜索 → 证据聚合（contextual summarization + LLM 重打分）→ 作答；`evidence_k=10`、`answer_max_sources=5`、`evidence_relevance_score_cutoff` | **Aval 评估框架 + LitQA2 基准**（唯一有学术基准的项目） | 有 `tests/`、多后端包（docling/pymupdf/pypdf）、LiteLLM 路由 | **证据打分与截断机制**：每块摘要按问题相关性再打分后才进答案；SciFlow 的 rerank 默认关闭且只对 12 条候选做一次 LLM 打分 |
| **STORM**（31.7k★, MIT） | `storm_wiki/engine.py` 四阶段 Runner | 多视角提问（perspective-guided questioning）驱动检索 → 大纲 → 分节生成 | 无 | Streamlit demo + `knowledge_storm` 包 | **预写作阶段的「多视角提问」**：先模拟不同立场提问再检索，覆盖面显著优于单主题检索；SciFlow 的「反共识变体」只作用在大纲阶段，不反哺检索 |

| **GPT-Researcher**（30.3k★, Apache-2.0） | planner/generator 两段 + `deep_agents` 递归 | 20+ retriever（含 openalex/pubmed/semantic_scholar）；`context/select.py` 提供 5 种 context filter（jev/keyword/embeddings/none），失败降级 keyword | `evals/context_filter` 基准 | skills 分层（curator/researcher/writer）、MCP server | **检索源广度**（20+）与 **context filter 可插拔**；SciFlow 只有 3 个学术源 + 本地库 |
| **AI-Scientist / v2**（14.8k★） | 线性 launch 脚本 | 无（跑代码做实验） | **LLM 审稿（ICLR 风格，reflection×5 + ensemble×5）** | v2 有 BFTS 树搜索 | **自动审稿的集成与反思**：多次采样 + 集成降低单次评审方差；SciFlow 的 7 维评审是单次调用 |

### SciFlow 真正领先的三点（代码可证）

1. **确定性质量门 + 客观/主观分离**：PaperQA2 有评估框架但用于 benchmark，不做「门禁」；STORM/GPT-Researcher 无质量门。SciFlow 的 `checkPaperQuality` 是硬指标（结构/篇幅/引用闭环/可读性/修辞/诚信），硬伤直接封顶 40。
2. **学术诚信检测**：六个对标项目无一家检查「自称没做实验却写实验结论」。这是 LLM 写论文最危险的失效模式。
3. **引用三级可追溯 + 七类体检**：`[n]` → citation → reference，且能检出「文献表凑数」「锚点断号」「重复 DOI」。

### 最该补的五点（按性价比排序）

| 优先级 | 缺口 | 对标依据 | 落地方式 |
|---|---|---|---|
| P1 | **证据级打分与截断** | PaperQA2 `evidence_relevance_score_cutoff` | rerank 默认开启（小模型），对候选块打 0-10 分并丢弃低分块，而非只排序 |
| P1 | **多视角检索** | STORM perspective-guided questioning | 在 `novelty-check` 后加一步：生成 3 个对立视角的检索词，扩充 `plan.searchStrategy.keywords` |
| P2 | **开工前澄清** | open_deep_research `clarify_with_user` | 流水线 create 前可选 1 轮澄清（研究问题/方法/目标期刊），跳过则用 topic 直跑 |
| P2 | **评审集成降方差** | AI-Scientist ensemble×5 | 7 维评审采样 3 次取中位数（成本 ×3，仅高质量档开启） |
| P3 | **检索源扩展** | GPT-Researcher 20+ retriever | 接 Semantic Scholar / PubMed（免 Key），复用现有 `ScholarHit` 归一化 |

## 四、尚未完成（明确遗留，非隐瞒）

- **完整 pnpm workspace 拆分**：`packages/*` 仍未进 `pnpm-workspace.yaml`，跨包引用靠桶文件 + tsconfig paths。真正拆包需要独立构建产物（tsc project references 或 tsup），会改变 Docker/桌面打包链路，属独立批次。
- **`documents.list` / `references.list` 无分页**：当前按项目全量返回。千篇级文献库会出现前端卡顿，需加 cursor 分页（会改前端调用契约）。
- **Docker 未本机验证**：本机 Docker daemon 未运行，Dockerfile/compose 仅静态审阅（历史记录显示曾实跑通过）。
- **e2e 需 Chromium**：`playwright test` 本机未跑（未安装浏览器），CI 中执行。
